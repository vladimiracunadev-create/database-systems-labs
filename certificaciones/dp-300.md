La credencial más directa para el rol de operación: planificación, seguridad, monitorización, automatización y alta disponibilidad sobre SQL Server y Azure SQL. Su temario es, casi punto por punto, la Parte 11 de este programa más partes de la 07, la 08 y la 09.

## 📊 Cobertura del programa: 70 %

`███████░░░` 69.9 % — media ponderada por el peso oficial de cada dominio.

**Método:** Se listan las subáreas oficiales del temario y se marca cuáles cubre el programa y con qué clases. La cobertura del dominio es subáreas cubiertas / subáreas totales, y el total es la media ponderada por el peso oficial del dominio. Es una medición, no una opinión.

El proveedor publica los pesos como rangos; se usa el punto medio de cada uno y se normaliza dividiendo por su suma real (102.5) en vez de por cien.

| Configure and manage automation of tasks | 15–20% | 0 de 3 subáreas | 0 % |

## 🎯 La brecha, y cómo cerrarla

La automatización en Azure (dominio de 15–20%) queda sin cubrir por diseño: este programa es neutral de proveedor. Ciérrala con la ruta de aprendizaje oficial de Microsoft Learn y con práctica en un portal de Azure real, y usa el resto del temario como está aquí.

## 🧭 Por dónde empezar aquí

- **Ruta recomendada:** [DBA / SRE de datos](../rutas/fiabilidad-y-operacion.md) — Que el sistema siga en pie y se pueda volver atrás: respaldo restaurado, planes de ejecución, réplica, objetivos de servicio y migraciones.
- **Laboratorios que la preparan:** [03 — Actualización perdida y sus tres correcciones](../labs/03-transactions/README.md) · [04 — Planes de ejecución y costo real de un índice](../labs/04-indexing/README.md) · [07 — Réplica, retraso y garantías de sesión](../labs/07-replication/README.md) · [08 — Respaldo, restauración y punto en el tiempo](../labs/08-recovery/README.md)
- **Para quién tiene sentido:** Quien opera SQL Server o Azure SQL y necesita una credencial reconocible en empresas grandes y en consultoría.
