## 📊 Cobertura del programa: 60 %

`██████░░░░` 60.1 % — media ponderada por el peso oficial de cada dominio.

**Método:** Se listan las subáreas oficiales del temario y se marca cuáles cubre el programa y con qué clases. La cobertura del dominio es subáreas cubiertas / subáreas totales, y el total es la media ponderada por el peso oficial del dominio. Es una medición, no una opinión.

El proveedor publica los pesos como rangos; se usa el punto medio de cada uno y se normaliza dividiendo por su suma real (95.0) en vez de por cien.

| Dominio del examen | Peso oficial | Base del cálculo | Cobertura |
|---|---|---|---:|
| Describe core data concepts | 25–30% | 4 de 4 subáreas | 100 % |
| Identify considerations for relational data on Azure | 20–25% | 1 de 2 subáreas | 50 % |
| Describe considerations for working with non-relational data on Azure | 15–20% | 0 de 2 subáreas | 0 % |
| Describe an analytics workload on Azure | 25–30% | 2 de 3 subáreas | 67 % |

Temario vigente comprobado el **2026-07-21**.

## 🎯 La brecha, y cómo cerrarla

Todo lo que es catálogo de servicios de Azure —SQL Database, Cosmos DB, Storage, Power BI— queda fuera. Es la mitad barata de estudiar: con el temario conceptual ya cubierto aquí, bastan unas horas de documentación oficial y del portal.

## 🧭 Por dónde empezar aquí

- **Ruta recomendada:** [Desarrollador de aplicaciones](../rutas/desarrollo-de-aplicaciones.md) — La base de datos vista desde el código que la usa: esquema como contrato, consultas correctas, concurrencia y despliegues sin caída.
- **Laboratorios que la preparan:** [01 — Fundamentos de SQL sobre el dominio educativo](../labs/01-sql-foundations/README.md) · [02 — Modelado políglota del mismo dominio](../labs/02-polyglot-modeling/README.md) · [05 — Elección por carga de trabajo en almacenes no relacionales](../labs/05-nosql-workloads/README.md)
- **Para quién tiene sentido:** Quien empieza y quiere una credencial de entrada reconocible, o quien necesita hablar con propiedad de datos sin ser especialista.
